# Left 4 Dead 2 development

L4D2 support is experimental and reuses the Portal 2 branch's i386 Mach-O
loader and native macOS bridges. Packaging and dependency-loading checks are
not evidence of playable gameplay. Keep observations tied to the tested Mac
build, macOS version, hardware, and loader revision.

## Building

Requirements are macOS 11 or later, Xcode command-line tools, Python 3, Rosetta 2
on Apple Silicon, an installed Steam client, and a Steam account that owns L4D2.
The loader is an x86_64 executable running through Rosetta, not an ARM64 rebuild
of Valve's game. No game binaries or data are included in this repository.

From `native/`:

```sh
make GAME=l4d2 bundle
```

The default source is
`~/Library/Application Support/Steam/steamapps/common/Left 4 Dead 2`. For another
library or a complete assembled Mac download:

```sh
make GAME=l4d2 SOURCE_GAME="/path/to/Left 4 Dead 2" bundle
```

The selected folder must contain `hl2_osx`, `left4dead2/gameinfo.txt`, and
`bin/launcher.dylib` or `bin/osx32/launcher.dylib`. The helper checks that the
launcher has an i386 Mach-O executable slice. `SOURCE_APP` is also accepted when
its `Contents/MacOS` contains the complete same tree. Separate depot folders are
not searched or combined. The Portal 2 converter GUI is unchanged.

The bundle target prepares the same private i386 C++ runtime as Portal 2. The
first build downloads Apple's 4.72 GB Lion archive, verifies it, and extracts
two libraries without running its installer or modifying system libraries.
Downloads are cached in `build/runtime-downloads`, and libraries in
`build/guest-runtime`. `GUEST_RUNTIME_DIR=/path/to/prepared/runtime` selects
another verified cache. Allow space for the copied game and another full game
tree during rebuild, in addition to the first download/extraction space.

The output is `build/L4D2-Compat.app`; its private game tree lives in
`Contents/SharedSupport/L4D2` and launcher image in
`Contents/SharedSupport/L4D2.image`. Source files stay untouched. Rebuilds stage a
fresh tree and retain existing `left4dead2/cfg/config.cfg`, `video.txt`, and
`videodefaults.txt`. Old libraries disappear when switching releases. These are
settings-preservation candidates; this does not promise campaign checkpoint
saves. Steam's existing ownership and authentication checks remain active.

```sh
make GAME=l4d2 run-game
make GAME=l4d2 promote-loader
```

`promote-loader` updates only the loader in an existing bundle without recopying
game data, including when the original game volume is unavailable. Rebuilding
and promotion reject symbolic links at their output write destinations before
copying or signing, so those writes cannot follow a link into the original game.
Local bundles are ad-hoc signed; public downloadable applications
require separate Developer ID signing and notarization.

## Launching and diagnostics

Open the compatibility app from Finder or launch it explicitly:

```sh
arch -x86_64 build/L4D2-Compat.app/Contents/MacOS/L4D2Compat -windowed -w 1280 -h 720 -novid
```

The original Mac launch uses `hl2_osx -game left4dead2 -steam`. The loader uses
L4D2's game directory and Steam AppID 550, and forwards Source command-line
arguments. Pass `-novid` to skip startup movies during diagnostic launches.
The bundle selects its title; raw-image diagnostic launches require
`LP32_GAME=l4d2` to select the title explicitly; bundled launches validate its known fingerprint.
Use `LP32_LOG_DIR=/path/to/logs` to isolate logs. `LP32_CAPTURE_FRAME=/path/frame.ppm`
captures a presented game frame. Import/Steam traces are diagnostic tools and
should remain disabled during performance measurements.
`LP32_SOURCE_FRAME_STATS=1` logs frame rate and frame-time percentiles every
240 presented frames; the existing `LP32_PORTAL_FRAME_STATS` name remains an alias.
For loading attribution, `LP32_FRAME_STATS=1 LP32_SOURCE_STATS_INTERVAL=30
LP32_SLOW_IMPORT_MS=1000` also reports the slow imports and the most costly
imports every 30 presentations. The interval accepts 1–240 (default 240).
Import totals are approximate across threads and include blocking and nested
callbacks; compare an unchanged launch without instrumentation for wall time.

## Loading performance

One instrumented before/after pair on 2026-10-13, using the audited Mac build
and M5 Max host described below, compared loaders `bb03364` and `780a58e` with
`-novid +sv_lan 1 +map c1m1_hotel`. After core import routing and hot string
handlers were memoized, the first 30 presentation intervals fell from 68.31 s
to 37.38 s (45% less time), with approximately the same 214.13 million versus
214.11 million imports. Source reported shader precaching of 13.455 s versus
6.809 s, for the same 1,024 vertex and 1,096 pixel programs. Summed presentation
intervals through the first report from the worker rendering thread fell from
198.57 s to 96.60 s; this milestone does not measure the exact moment the HUD
became ready. A later capture showed the hotel rooftop, HUD and three bots.

Both windows were unfocused and profiling was enabled. This is one sequential
pair; filesystem/driver cache warmth and instrumentation overhead were not
controlled. Repeat without profiling and across maps before making broader
loading-time or gameplay-frame-rate claims. L4D2 support remains experimental.

The separate synthetic real-i386 benchmark measured 4.7–4.9 times lower cost
for the tested string import workloads, with matching results and buffer
guards. That ratio describes import workloads, not whole-game loading time.
From `native/`, run:

```sh
make build/game_loader
LP32_I386_LINKER=/path/to/i386-capable/ld64 LP32_TEST_GAME=l4d2 \
  python3 tests/test_dispatch_benchmark.py
```

The runner alternates memoized and `LP32_NO_FAST_IMPORTS=1` launches and reports
medians over six samples per mode. It needs no game files and makes no timing
pass/fail assertion.

## Movie playback

The Mac game uses the removed QuickTime C API. The compatibility loader supplies
the Movie Toolbox and QuickDraw subset exercised by its original `valve_avi`
library, backed by AVFoundation. The original `IQuickTime001` interface and
Source material/texture code remain active. Startup movies are enabled unless
`-novid` is passed, and the original menu code controls background looping.
Apple documents that the [QuickTime C APIs are unavailable to 64-bit applications](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/Carbon64BitGuide/OtherAPIChanges/OtherAPIChanges.html).

AVPlayer plays movie audio and an
[AVPlayerItemVideoOutput](https://developer.apple.com/documentation/avfoundation/avplayeritemvideooutput)
supplies BGRA frames to guest texture storage. Movie, file, audio-context and
QuickDraw references use separate guest handles. Frame queries use the files'
actual presentation timestamps, including the intro's 24000/1001 cadence.
Seeking waits for completion before copying another frame, and decoder startup
or repeated frames preserve the last image. Unsupported API options return
errors; the shim does not provide the complete historical QuickTime API or a
Bink decoder. This Mac build's original movie code selects its supplied `.mov`
files.

The audited movies contain H.264 video. The intro has big-endian PCM audio,
`valve.mov` has ALAC audio, and the menu/rating movies have no audio. Native
tests decoded changing frames from the intro, logo and menu. Generated movie
fixtures cover timestamp advancement/end, seeking, looping, paused playback,
guest output widths and disposal; generated i386 fixtures exercise real
decoder-to-guest texture-buffer copying. These automated checks use muted
playback. An interactive run subsequently rendered the logo and complete intro
in the game window, with video and audible movie playback confirmed by the
tester. Sustained menu looping and campaign acceptance remain separate checks.

## Checks

Synthetic packaging and existing bridge regressions need no L4D2 copy:

```sh
make test-l4d2-source test-portal2-converter
make test-game-profile test-macho-file test-guest-dyld test-steam-abi test-steam-startup
make test-source-steam-startup test-l4d2-runtime
make test-gl-shader-bridge test-cursor-state test-hi-mouse
make test-arb-program-guard test-arb-sampler-usage
make test-audio-converter test-quicktime-bridge
```

The packaging fixtures reject missing/non-Mac launchers, validate flat and
app-wrapper layouts, protect source/output containment, avoid writes through
copied links, preserve settings, and remove obsolete libraries. The original
Portal source-copy/converter checks still run after sharing the copier.
They also exercise the real Make promotion recipe against linked loader, plist,
and icon destinations, and verify promotion with an unavailable game source.

With a real complete Mac installation:

```sh
make GAME=l4d2 SOURCE_GAME="/path/to/Left 4 Dead 2" test-l4d2-loader
python3 tests/test_l4d2_bundle.py --source "/path/to/Left 4 Dead 2"
```

These build/copy/sign/load checks do not enter gameplay. The integration test
uses a disposable bundle, rebuilds it with newer settings fixtures, checks
obsolete-library removal and loader promotion, and verifies the source remains
unchanged. It can need two game-sized copies during rebuild.
Add `--copy-only` to test actual copying and rebundling before the loader/runtime
is ready, without downloading runtime libraries, signing, or executing the game.

Gameplay acceptance requires at least 30 minutes of offline campaign play with
bots, including two maps and a chapter transition. Check world/HUD rendering,
normal music and effects, keyboard/mouse control, windowed/fullscreen modes,
focus loss/return, and clean quit. Change settings in game and verify the actual
written files survive relaunch and rebundling. Record frame performance without
an FPS pass threshold. Online multiplayer, voice chat, controller play,
Workshop content, and every historical build require separate validation.

Interactive campaign boots reached `c1m1_hotel`, connected to the local server
and rendered the rooftop world, HUD and three bot teammates. The tester played
down the initial stairs and confirmed movement, game audio and fullscreen,
then quit normally. The engine returned successfully with no trapped import.
Separately, an engine-command test changed `volume` from 1.0 to 0.61, wrote the
configuration, rebuilt the complete bundle, and relaunched without a volume
override. The fresh engine wrote 0.61 again and quit cleanly. The tester's
original configuration and video settings were restored afterwards.
The sustained 30-minute two-map/chapter-transition acceptance run and an
explicit focus loss/return check remain unverified.

## Audited Steam Mac build

The initial audit used Steam public build 23990068, with Mac depot 553 manifest
3778609098660866963. The installed `hl2.sh` selects `hl2_osx`; its launcher UUID
is `45DE3007-ADDB-36ED-BE1C-F1FF3383D658`. The i386 entry is `0x1d90`, mapped
image end `0x4000`, and exported `_main` is `0x1e00`. These values were checked
with Mach-O load commands, symbols, and disassembly.

`libtier0` passes its allocated thread context directly to `pthread_create`.
The launcher's `objc_msgSend_stret` callers adjust the stack after the callee's
four-byte hidden-result-pointer pop. These observations select the profile's
explicit thread-argument and structure-return conventions.

| `bin/launcher.dylib` | `d45e6ec9dbca80a515580adea720964c1b6921da415320af76b29e4aa0785a97` |
| `bin/libtier0.dylib` | `6a6c6260e2c015e6424ba97ec630aff40a34eba3d1eefdd6bfe4f6a5f6e77762` |

The supplied Steam API includes i386, x86_64, and arm64 slices. Its core
interface versions match the existing bridge. The client also initializes the
public `STEAMTIMELINE_INTERFACE_V001` interface; its four methods are appended
without changing existing generated ordinals. Optional private GameStats and
Steam Video interfaces are not claimed as supported. The loader sets AppID 550
explicitly: the shipped `bin/steam_appid.txt` contains the authoring-tool AppID
879 and must not determine game identity.

The fixture run used macOS 27.0 (26A428), an Apple M5 Max Mac17,7 with 128 GiB
RAM, and Xcode 27's beta SDK. This Xcode linker rejects i386 fixture links.
`LP32_I386_LINKER=/path/to/i386-capable/ld64` selects a separate linker for test
fixtures without changing the active developer tools. The local test tool was
built from cctools-port commit `904de2a71d4da6a9b30d2efaf912a10ddc7d9ddb` and
apple-libtapi commit `fa9443738c1a18accef4244732ec6d6ee97a8133`. These tools and
compiled fixtures are not distributed with the game bundle.

The i386 decoder fixture can additionally use a real movie without copying it:

```sh
LP32_QUICKTIME_TEST_MOVIE="/path/to/Left 4 Dead 2/left4dead2/media/l4d2_background01.mov" \
  make test-l4d2-runtime
```

On a sandboxed development host, AVFoundation's decoder may require running
the movie checks outside that development sandbox. Ordinary app launches still
use the standard macOS media services.
