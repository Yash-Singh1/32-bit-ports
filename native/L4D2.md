# Left 4 Dead 2 development

L4D2 support is experimental and reuses the Portal 2 branch's i386 Mach-O
loader and native macOS bridges. Packaging and dependency-loading checks are
not evidence of playable gameplay. Keep observations tied to the tested Mac
build, macOS version, hardware, and loader revision.

## Building

Requirements are macOS 11 or later, Xcode command-line tools, Python 3, Rosetta 2
on Apple Silicon, an installed Steam client, and a Steam account that owns L4D2.
The loader is an x86_64 executable running through Rosetta, not an ARM64 rebuild
of Valve's game. No game binaries or data are included in this repository.

From `native/`:

```sh
make GAME=l4d2 bundle
```

The default source is
`~/Library/Application Support/Steam/steamapps/common/Left 4 Dead 2`. For another
library or a complete assembled Mac download:

```sh
make GAME=l4d2 SOURCE_GAME="/path/to/Left 4 Dead 2" bundle
```

The selected folder must contain `hl2_osx`, `left4dead2/gameinfo.txt`, and
`bin/launcher.dylib` or `bin/osx32/launcher.dylib`. The helper checks that the
launcher has an i386 Mach-O executable slice. `SOURCE_APP` is also accepted when
its `Contents/MacOS` contains the complete same tree. Separate depot folders are
not searched or combined. The Portal 2 converter GUI is unchanged.

The bundle target prepares the same private i386 C++ runtime as Portal 2. The
first build downloads Apple's 4.72 GB Lion archive, verifies it, and extracts
two libraries without running its installer or modifying system libraries.
Downloads are cached in `build/runtime-downloads`, and libraries in
`build/guest-runtime`. `GUEST_RUNTIME_DIR=/path/to/prepared/runtime` selects
another verified cache. Allow space for the copied game and another full game
tree during rebuild, in addition to the first download/extraction space.

The output is `build/L4D2-Compat.app`; its private game tree lives in
`Contents/SharedSupport/L4D2` and launcher image in
`Contents/SharedSupport/L4D2.image`. Source files stay untouched. Rebuilds stage a
fresh tree and retain existing `left4dead2/cfg/config.cfg`, `video.txt`, and
`videodefaults.txt`. Old libraries disappear when switching releases. These are
settings-preservation candidates; this does not promise campaign checkpoint
saves. Steam's existing ownership and authentication checks remain active.

```sh
make GAME=l4d2 run-game
make GAME=l4d2 promote-loader
```

`promote-loader` updates only the loader in an existing bundle without recopying
game data, including when the original game volume is unavailable. Rebuilding
and promotion reject symbolic links at their output write destinations before
copying or signing, so those writes cannot follow a link into the original game.
Local bundles are ad-hoc signed; public downloadable applications
require separate Developer ID signing and notarization.

## Launching and diagnostics

Open the compatibility app from Finder or launch it explicitly:

```sh
arch -x86_64 build/L4D2-Compat.app/Contents/MacOS/L4D2Compat -windowed -w 1280 -h 720 -novid
```

The original Mac launch uses `hl2_osx -game left4dead2 -steam`. The loader uses
L4D2's game directory and Steam AppID 550, and forwards Source command-line
arguments. Pass `-novid` to skip startup movies during diagnostic launches.
The bundle selects its title; raw-image diagnostic launches require
`LP32_GAME=l4d2` to select the title explicitly; bundled launches validate its known fingerprint.
Use `LP32_LOG_DIR=/path/to/logs` to isolate logs. `LP32_CAPTURE_FRAME=/path/frame.ppm`
captures a presented game frame. Import/Steam traces are diagnostic tools and
should remain disabled during performance measurements.

## Checks

Synthetic packaging and existing bridge regressions need no L4D2 copy:

```sh
make test-l4d2-source test-portal2-converter
make test-game-profile test-macho-file test-guest-dyld test-steam-abi test-steam-startup
make test-source-steam-startup test-l4d2-runtime
make test-gl-shader-bridge test-cursor-state
make test-arb-program-guard test-arb-sampler-usage
```

The packaging fixtures reject missing/non-Mac launchers, validate flat and
app-wrapper layouts, protect source/output containment, avoid writes through
copied links, preserve settings, and remove obsolete libraries. The original
Portal source-copy/converter checks still run after sharing the copier.
They also exercise the real Make promotion recipe against linked loader, plist,
and icon destinations, and verify promotion with an unavailable game source.

With a real complete Mac installation:

```sh
make GAME=l4d2 SOURCE_GAME="/path/to/Left 4 Dead 2" test-l4d2-loader
python3 tests/test_l4d2_bundle.py --source "/path/to/Left 4 Dead 2"
```

These build/copy/sign/load checks do not enter gameplay. The integration test
uses a disposable bundle, rebuilds it with newer settings fixtures, checks
obsolete-library removal and loader promotion, and verifies the source remains
unchanged. It can need two game-sized copies during rebuild.
Add `--copy-only` to test actual copying and rebundling before the loader/runtime
is ready, without downloading runtime libraries, signing, or executing the game.

Gameplay acceptance requires at least 30 minutes of offline campaign play with
bots, including two maps and a chapter transition. Check world/HUD rendering,
normal music and effects, keyboard/mouse control, windowed/fullscreen modes,
focus loss/return, and clean quit. Change settings in game and verify the actual
written files survive relaunch and rebundling. Record frame performance without
an FPS pass threshold. Online multiplayer, voice chat, controller play,
Workshop content, and every historical build require separate validation.
