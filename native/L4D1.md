# Left 4 Dead development

Experimental support for the original Left 4 Dead Mac installation, Steam AppID
500. The tested installation is build 26384159, with Mac depot 504. It uses
`hl2_osx`, `bin/launcher.dylib`, and `left4dead/gameinfo.txt`.

Build from `native/` with a complete Mac game folder:

```sh
make GAME=l4d1 SOURCE_GAME="/Volumes/Expansion/SteamLibrary/steamapps/common/left 4 dead" bundle
open build/L4D1-Compat.app
```

The bundle contains its own game data and private guest C++ runtime. Steam must
be open and signed in to an account that owns Left 4 Dead. The launcher supplies
AppID 500 and `-game left4dead -steam -novid -nosound`. Original game files are only read.
Settings in the existing converted app survive rebuilding. The GUI converter
still targets L4D2; L4D1 packaging currently uses Make.

L4D1 and L4D2 have identical launcher address fingerprints. Their bundle image
names select separate profiles. An explicit image launch must set
`LP32_GAME=l4d1`; an ambiguous unhinted image fails rather than selecting L4D2.

The port adds historical Steam interface metadata, callback-registration
tracking, QuickTime symbol lookup through RTLD_DEFAULT, font activation from
FSRef, ATI front/back stencil conversion, and the legacy calls encountered
in Chromium and Miles initialization. On Rosetta, the old PCI accelerator scan
is unavailable, so L4D1 retains CGL renderer information. Callback registrations
still reach the original guest Steam API, and authentication still reaches the
installed native Steam client. Unknown registered callback layouts fail.

Historical Steam declarations are recorded in `tools/steam_legacy_abi.json`,
including source links and header hashes. Regenerating `steam_abi.inc` appends
those interfaces to the existing metadata. Unsupported pointer-bearing records
remain marked with `?`; they are not passed to native Steam as guessed layouts.
FriendGameInfo_t has the same 24-byte layout in both ABIs, with fields at offsets
0, 8, 12, 14, and 16. Its output is covered by guarded i386 fixture calls.

Useful checks:

```sh
make test-l4d1-source test-game-profile test-steam-abi
make test-l4d1-runtime
make GAME=l4d1 SOURCE_GAME="/path/to/left 4 dead" test-l4d1-loader
```

The runtime fixtures exercise registration forwarding and private callback
filtering, old client method ordinals, friend-game output guards, file locking
with a length above 4 GiB, Mach task output guards, FSRef font loading, and the
shared loader bridges across four executable layouts. The GL buffer self-test
also checks different ATI front/back stencil functions against native GL state.

The first real No Mercy load hit the existing Core Audio allocator assertion
in AudioQueueStart, with a 0x8040-byte request. Keep `map-audio-crash.log` and
the corresponding macOS crash report when investigating this failure.

Nested guest callbacks now start below the enclosing import's live guest stack.
The previous fixed 64 KiB spacing could overlap Source's deeper loading frames.
A 96 KiB i386 stack fixture reproduces the corruption before this change and
passes afterward. The four-layout runtime fixtures also pass for Portal 2 and
L4D2 with the new placement. NSNotification callback arguments use borrowed
handles that the guest can retain; temporary notifications no longer consume
the fixed persistent proxy table.

The sound-disabled No Mercy test rendered the opening rooftop, its HUD,
weapons, rain, and survivor bots. The load took roughly eight minutes on this
external-drive copy. Input, a full campaign, multiplayer, audio after the stack
fix, and visual accuracy remain unverified.

The Compat app is the user entry point. L4D1 defaults to `-novid -nosound` for
Finder and Dock launches. `LP32_L4D1_AUDIO=1` enables audio for diagnostic runs.
The game image, copied Steam data, and private C++ runtime remain inside the app.

The packaged experiment at `/Volumes/Expansion/mac-ports/l4d1-native/L4D1-Compat.app`
was ad-hoc signed and opened through Launch Services without command-line
arguments or environment overrides. Its visible menu is recorded in
`app-launch-menu.png` beside the bundle. Initial macOS assessment delayed the
first launch by several minutes; a subsequent launch reached the menu in
roughly one minute. No separate launcher file is needed.

After rebasing onto portal2 `df6b0f8`, the runtime forwards `_issetugid`
to native libc. Chromium calls this during loading; the previous unsupported
import terminated the process. The i386 libc fixture checks the unprivileged
result and errno preservation across all four runtime layouts.

The rebased build has rendered No Mercy at 1920x1200 with survivor bots,
HUD, rain, and weapons. Console-driven movement changed the player position;
firing reduced pistol ammunition and rendered the muzzle flash. This run was
kept in the background while the user worked. Keyboard/mouse input and
foreground frame rate were not assessed in that run. Audio remains disabled
by default. See the experiment folder for `post-rebase-rooftop.png`,
`post-rebase-moved.jpg`, and the runtime/frame-time logs.

A console `changelevel l4d_hospital02_subway` also completed. The new
server/client connected, all three survivor bots spawned, and a nonzero
player position and rendered subway frame were captured. The internal-copy
run lasted about eighteen minutes before an explicit console quit. Loading
remained slow and background frame rates were low; this is functional
verification, not confirmation of smooth foreground performance.

That quit exposed `_NSUnLinkModule` in Miles cleanup. Its bridge now
validates the module handle and published option bits, uses the existing
guest-dyld close policy, and returns false for invalid handles. Modules remain
pinned just as they do for guest `dlclose`. Four-layout runtime fixtures cover
valid handles, invalid handles, invalid options, and continued symbol lookup.
